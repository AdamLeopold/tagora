01 · 验证体系

六层实测，
把描述变成证据

  1. L1
    静态分析依赖树、许可证、恶意模式，声明权限与实际行为是否一致
  2. L2
    功能测试标准沙箱中跑领域测试集，得出质量指标
  3. L3
    边界与极端输入超大文件、空输入、畸形格式、多语言、并发
  4. L4
    对抗测试提示注入、恶意文件、试图出网或读取环境
  5. L5
    资源与成本延迟、内存、显存、token，按硬件类别分别测量
  6. L6
    线上复检上架后抽样真实调用再评估，分数随表现变化

02 · 防作弊

考题保密，成绩公开

任何公开的评测都会被针对性优化；工具甚至可能识别自己正在被测试，考试时表现良好、上线后偷工减料。Tagora 用四个机制让“刷分”无利可图。

隐藏轮换题库

每个领域维护大题库，每轮随机抽取子集并定期引入新题，只公开少量样例题。

流量不可区分

复检调用与真实调用走同一入口、同一支付与加密流程，Worker 无法判断哪次是考试。

代码哈希绑定

能力卡只对被测过的代码哈希有效。执行前远程证明出示当前哈希，偷换代码立刻暴露。

动态信用分

初始分由 L1–L5 决定，之后由线上复检与调用方反馈持续修正；显著偏离即降级或下架。

03 · 能力卡

agent 读的不是 README，
是能力卡

能力卡是验证体系的输出，也是路由和定价的唯一依据。它绑定在「代码哈希 × 硬件类别」上，对调用方完全可见，但不包含测试题本身。

  • 身份工具版本、代码哈希、硬件类别、信任档位
  • 质量各子场景得分与评估置信度
  • 边界已知失败模式与不支持的输入
  • 成本单次价格、P50 / P95 延迟
  • 数据流向是否出网、是否调用第三方模型
  • 信用复检次数、最近复检、分数趋势
